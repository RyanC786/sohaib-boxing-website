## Migration protections

Records live in a non-exposed private schema; all tables also have RLS and no browser grants. Customers see only their orders through an authenticated RPC. Scanner lookup requires MFA, active staff membership, an event assignment and an open admission window. Lookup alone does not admit. Admission locks the order and ticket, verifies paid status, changes a valid ticket to used and records the staff action in the same transaction. Token hashes are unique. QR codes must use at least 32 random bytes generated by the backend, not names, emails or order counters.

## Marketing

The proposed checkbox is unticked: “Email me about future Sohaib Mohammed events and ticket releases. I can unsubscribe at any time.” Confirm the actual organiser/controller name before launch. Link the privacy notice beside the form. Ticket purchase must not require this choice.

Consent records store wording version, source and request/confirmation/withdrawal timestamps. An opt-in request stays pending until the email-confirmation handler verifies a single-use expiring token. The sender must check current consent and suppression immediately before every promotional send. Unsubscribe must work without account login through a signed token, including email-provider one-click unsubscribe handling. A later purchase never overrides an unsubscribe. Never import an external ticket provider's customers as subscribers without appropriate permission/evidence.

Service messages (ticket delivery, material changes to the purchased event) are separate from promotions. The template system needs purpose labels to enforce that distinction. No marketing campaign or customer email is sent by this migration.

## Retention

There is no universal UK GDPR retention duration for this dataset. Set a documented purpose-based policy with the organiser: operational attendee details/check-ins, payment/accounting records, marketing consent evidence and suppression records need separate treatment. Review marketing data periodically rather than keeping it indefinitely by default. Withdrawal stops marketing promptly; retain only the minimal restricted suppression evidence needed to avoid contacting someone again.

The schema has `personal_data_delete_after`, `legal_hold`, `anonymised_at` and marketing `review_after` fields. **No deletion schedule has been enabled**: first agree durations, accounting/dispute requirements, erasure/export handling and backup expiry. Do not delete order evidence required for a valid legal obligation or live dispute merely because marketing consent was withdrawn.

Also test account recovery, password rotation, refresh expiry, logout, accessibility and camera support on actual iOS/Android devices.
